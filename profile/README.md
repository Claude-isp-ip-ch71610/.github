<p>「推荐哪家」这个问题，问的人多，答的人各有各的立场。更有用的问法是：我手上这批号该怎么分、出口按什么粒度切、新市场怎么小成本验证。这三件事定下来，供应商之间的差异反而变得可比较。这篇给的是决策清单，不是排行榜：每一项写清判定条件，达不到条件时对应什么风险，照着打勾就行，避免一边试一边改、风险越试越乱。</p>

<h2>一、先定三件事，再谈选哪家</h2>
<p>选型之前先回答三个问题：手上账号怎么分组、出口按国家还是按城市切、新市场用多少资源验证。这三个答案直接决定你要的是「大池子低重复」还是「小池子强隔离」，买错了方向，再便宜也是浪费。</p>
<h3>第一件：池子按什么维度分</h3>
<p>最常用的是按账号年龄分：注册满半年、有稳定订阅记录的老号一组；30 天内的新号一组；专门用来试新地区、随时可弃的测试号一组。分组的目的是让风险不串——新号在验证期被拦的概率天然高于老号，混在一池里，一次异常就会拖累整组。</p>
<h3>第二件：地区切分到什么粒度</h3>
<p>粒度有三个层次：国家、城市、ASN。只按国家切，同国不同城市的出口可能相距上千公里，登录地来回跳；按城市切，登录地能稳住，但可选城市有限；按 ASN 切最细，适合对运营商归属也有要求的场景。多数团队做到城市级就够，除非账号资料里明确写了运营商。</p>

<h2>二、老号与新号分池：可执行清单</h2>
<p>分池听起来抽象，落到操作上就是两张资源表、两套参数、两条巡检线。做完之后，任何一次异常都能先定位到组，再定位到号。</p>
<h3>分的是资源，不是账号标签</h3>
<p>常见误区是只在管理表里打个「老号」标签，出口还是共用。真正的分池要求出口段不重叠：把两组使用的 IP 段列出来做交集，交集必须为空。检查办法是把两组的出口地址各导出十几条，比对前三段，出现重复就说明还在共用同一段家宽。</p>

<h2>三、新市场验证：从一条线到一个地区</h2>
<p>开拓新地区时最忌讳一次铺开。正确顺序是：一条线跑通、一个小批跑稳、再按地区复制。三段的资源投入大约是 1 比 5 比 20。</p>
<h3>选地区看三个信号</h3>
<p>第一是账号资料里已经写了什么——注册时填的国家、语言、时区，出口应当与之对齐，凭空换一个不相关地区反而更可疑。第二是业务实际发生在哪——客服常驻的城市、竞品所在的区域。第三是该地区出口的可获得性，某些城市家宽资源稀缺，报价高且重复率高，先确认有没有稳定货源再谈其他。</p>
<h3>验证期的最小配置</h3>
<p>一条出口、两个号、七天。第一天跑注册或登录流程，第二到三天跑日常对话，第四天做一次订阅页访问，第五到七天观察是否有额外的验证要求。七天里如果出现两次以上验证，说明这条线在该地区的信誉不够，换一条再试，别急着放大。</p>

<h2>四、交付与验收清单：逐条打勾</h2>
<p>清单的价值在于把「感觉可以」变成「确认过」。下面这些项，建议在开通当天和跑满一周各过一遍，任一项不通过就先不放大。</p>
<h3>开通当天要确认的五项</h3>
<p>出口归属城市与承诺一致；运营商类型是住宅而非机房；同一账号重复查询三次归属稳定；连接建立时间在可接受范围（通常 300 毫秒以内）；配置文件里的时区与出口城市匹配。</p>
<h3>跑满一周要复核的三项</h3>
<p>七天内的掉线次数、是否需要重新登录、出口归属是否发生过漂移。三项都有记录，才能判断这条线是「能用」还是「能长期用」。</p>

<h2>常见问答</h2>
<h3>老号一定要单独占一个池子吗？</h3>
<p>答：账号数超过十个就建议分。老号的价值在于历史记录，一旦被牵连损失远大于出口费用。三五个号的小规模可以暂不分池，但出口段仍要保证不与其他业务重叠。</p>
<h3>按城市切会不会资源不够用？</h3>
<p>答：取决于城市。一线城市家宽资源充足，小众城市常见只有一两家能供。做法是主力业务放在资源足的城市，测试性业务再考虑小众地区，别把核心账号押在稀缺资源上。</p>
<h3>新市场验证要花多少钱？</h3>
<p>答：一条线七天，按小时或按天计费，通常几十元到一两百元，仅供参考。相比直接铺二十个号再发现地区不合适，这个成本几乎可以忽略。</p>
<h3>供应商说池子大重复率低，怎么验证？</h3>
<p>答：抽十条出口查前三段与 ASN，看是否有重复；再在不同日期重复抽样，看是否抽到同一批地址。抽两次就重复的，说明池子实际很小，宣传口径当不得真。</p>

<h2>合规提示</h2>
<p>清单中的判定标准用于评估网络资源质量，不用于规避平台风控。任何情况下都不应通过伪造资料、批量注册等方式绕过平台限制。</p>
<p>涉及跨境数据传输时，应遵守所在地法律及平台条款，账号资料的真实性由使用者自行负责。</p>
